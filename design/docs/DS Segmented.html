Components / Segmented control

Segmented control

A compact row of 2–4 mutually-exclusive options that filters or switches a view in place. Use it for short, equal-weight choices where seeing all options at once helps — queue filters, list view modes.

Beta2–4 segments

Anatomy

A bordered track with a 3px inset, holding equal segments. The selected segment lifts to a white pill; the rest stay quiet. An optional count chip rides in each segment.

Filter with counts (amber for pending) · icon view toggle.

States

Segmented vs. tabs vs. select

Segmented filters/switches content in place (2–4 options). Tabs navigate between larger sections of a page. Select is for longer lists. If options won't fit on one short row, it's not a segmented control.
NeedUse
2–4 short filters, all visibleSegmented control
Page sections (Overview, Members…)Tabs
5+ options or long labelsSelect

Do & don't

Do

Short, parallel labels; one always selected.

Don't

Don't cram long labels or 5+ options — use a select.

Accessibility

  • Group has role="tablist" (or radiogroup when it filters); segments are buttons with aria-pressed/aria-selected.
  • Arrow keys move between segments; one is always selected.
  • Selected state shown by the raised pill, not color alone.
  • Count chips that signal attention include visually-hidden context ("2 pending").

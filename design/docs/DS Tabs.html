Components / Tabs

Tabs

Tabs switch between peer views of the same context without leaving the page. syoksheet uses underline tabs for in-page sections and a segmented control for filtering a single list.

Beta 2 types

Underline tabs

The default. A row of labels with a teal underline marking the active view. Each tab may carry an icon and a count.

Active panel content shows here.
Active tab: teal underline + darker label. Counts use mono; warning counts go amber.

Segmented control

For filtering one list in place (All / Pending / Approved). Lower-emphasis than tabs — it changes what's shown, not which view you're in.

Pill group, active segment filled. Use for ≤5 mutually exclusive filters.

Behavior

  • Tabs vs. pages: use tabs only for tightly-related peer views. If a view deserves its own URL or sidebar entry, make it a page (as the org console did).
  • One active tab always; never zero, never two.
  • Preserve state per tab where practical — switching away and back shouldn't reset a half-filled form.
  • Few tabs: 2–6. Past that, reconsider the structure.
  • No horizontal scroll — tabs wrap if the row is tight; they never become a scroller.

Do & don't

Do

Segmented control to filter a list of brags.

Don't

Too many tabs — this should be a sidebar section or sub-navigation.

Accessibility

  • Tab list uses role="tablist"; each tab role="tab" with aria-selected.
  • Arrow keys move between tabs; Enter/Space activates. The active panel has role="tabpanel".
  • Active state shown by underline weight and aria-selected, not colour alone.
  • Focus ring is visible on keyboard focus of each tab.

Components / Table

Table

A simple table lists a short, read-mostly set of records — sessions, a team summary — where columns align for scanning. For long lists that need search, sort, selection or pagination, use the Data table instead.

Beta read-only

Anatomy

A bordered card wraps the header row and the body rows — nothing else. No toolbar, no pagination. It shares the Card container spec.

Columns & alignment

  • Text left, numbers right. Numeric and date columns right-align and use mono so digits line up.
  • Identity column first — avatar + name + secondary line (email), as a unit.
  • One row action at most — a single ⋯ or link, right-aligned. If rows need many actions or bulk operations, you want a Data table.
  • Status as a pill, not coloured text, so it's scannable down the column.

States

  • Row hover tints to --n-50; an actionable row shows a pointer cursor.
  • Empty — swap the body for the Empty state component, keeping the header.
  • Loading — skeleton rows matching the column layout; never a centred spinner alone.
  • Outgrows simple — once a list needs search, sort, selection or pages, graduate it to the Data table.

Accessibility

  • Use real <table> / <th> / <td> with scope on headers.
  • Row-action controls have an aria-label naming the row ("Actions for Mei Ono").
  • Hover tint is decorative only — it never carries meaning.

Bits UI mapping

Which headless primitive backs which spec page, what has no primitive and is built here, and what Bits UI offers that later phases will want. The spec pages describe behavior; this page says what implements it.

Svelte 5bits-ui

Setup

One dependency, pinned exactly like every other package here. Bits UI ships behavior and accessibility and almost no styles, which is the reason it was chosen: every pixel stays ours.

ddev exec npm install bits-ui
Import per component: import { Dialog } from 'bits-ui'
  • Style only with semantic tokens. A component never reaches for a primitive such as --n-600.
  • Never restyle a shared component locally. If a screen needs a different look, the spec changes.
  • Do not reimplement behavior a primitive already has. Focus traps, roving focus, dismissal and positioning are the whole reason for the dependency.

Built in house

Bits UI has no primitive for these, or we chose not to use one. Toast and file upload are the two that surprise people.

Spec pageWhy
ToastNothing in Bits UI covers it. Region, stacking, timers and the reduced-motion path are all ours, and the queue state is the SSR module-scope hazard in .ai/rules/ts.md.
File uploadNo primitive. A native <input type="file"> plus our own drag target and progress.
Table, Data tableBuilt in house by decision, not by absence. No TanStack Table and no TanStack package for anything else. Pagination is available for the pager.
AlertInline feedback, so presentational. AlertDialog is a modal and is not this.
Badge, Tag, Card, Skeleton, Empty state, Verification markPresentational. No behavior to borrow.
BreadcrumbA nav and an ordered list. The truncation ramp is in App shell.
Sidebar nav, App shellLayout. NavigationMenu is for menubars and does not fit.

Badge

A badge is a small, read-only label that states the status of the thing it sits beside — a brag's verification, a request's state, a plan tier. Badges describe; they're never interactive.

Beta 6 variants

Variants

Each variant maps to a meaning. Status badges (verified / pending / unverified) are the load-bearing ones; info / error / count cover the rest.

Anatomy & spec

A badge is a pill: optional leading glyph, mono text, hairline border. Mono type signals "system status," distinct from the sans of interactive elements.

Badge vs. tag vs. button

Three pill-shaped elements that are easy to confuse. The difference is interaction and purpose.

ElementInteractive?PurposeType
BadgeNoStates a statusMono
TagSometimes (filter)Labels a skill / categorySans
ButtonAlwaysTriggers an actionSans, 600

Do & don't

Do
Pending

Glyph + word, so meaning survives without colour.

Don't

A bare colour dot with no label or glyph — meaningless to many users.

Badges are not buttons. If a user can act on it, it's a button or a tag-filter — not a badge.

Accessibility

  • Status is conveyed by glyph + text, never colour alone.
  • Count badges include visually-hidden context (e.g. "2 pending verifications") for screen readers.
  • Badges are inline text, not focusable; they never receive a tab stop.
  • All badge colour pairs meet WCAG AA on white.

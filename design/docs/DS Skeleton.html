Components / Skeleton

Skeleton

Placeholder shapes that stand in for content while it loads, mirroring the layout that's about to appear. They keep the page stable and feel faster than a spinner because structure arrives first.

Betashimmer

Anatomy

Neutral blocks with a soft left-to-right shimmer, shaped like the real elements — a circle for an avatar, lines for text, pills for tags. They occupy the exact space the content will.

A brag-card skeleton — avatar circle, name line, two title lines, tag pills.

Matching the layout

A skeleton mirrors the component it replaces. A table skeleton keeps the columns; a card skeleton keeps the card shape. The closer the match, the less the page shifts when content lands.

Table skeleton keeps the column grid so the header stays put.
Skeleton vs. spinner: use a skeleton when you know the shape of what's coming (a list, a card, a page). Use a spinner only for a small in-place wait where layout is already settled.

Do & don't

Do

Match the real layout's shapes and count. Keep any header/toolbar visible above the skeleton.

Don't

Don't show skeletons for more than a moment, or use them when an empty state is the real answer.

Accessibility

  • The loading region sets aria-busy="true" and a label like "Loading brags".
  • Skeleton shapes themselves are aria-hidden — they carry no meaning for screen readers.
  • Shimmer honours prefers-reduced-motion: it falls back to a static neutral block.
  • Don't trap focus in the skeleton; move focus to the content once it loads.

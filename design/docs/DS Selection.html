Components / Checkbox & radio

Checkbox & radio

Form selection controls. A checkbox toggles an independent option (or several); a radio picks exactly one from a set. Both are part of a form you submit — not instant settings (use a switch for those).

Beta2 controls

Checkbox

A square that checks with a teal fill. Supports an indeterminate state for "some of a group selected".

unchecked · checked · indeterminate · disabled

Radio

A circle that fills its ring when selected. Exactly one option in a group can be active.

One active per named group.

Radio cards

When each option needs a description, wrap the radio in a selectable card. The whole card is the target; the selected one tints teal. Used for verification policy and visibility.

Whole card clickable; selected card tints teal-50 with a filled ring.

Checkbox vs. radio

UseControl
Several independent on/off optionsCheckbox (one each)
One choice from a mutually-exclusive setRadio group
Single option that applies immediatelySwitch (not these)
2–3 short exclusive choices in a rowSegmented control
Radios never un-select to nothing. If "none" is valid, add an explicit "None" option or use checkboxes instead.

Do & don't

Do

Stack options vertically with clear labels. Use radio cards when each choice needs a sentence of explanation.

Don't

Don't use radios for a single yes/no (use a checkbox or switch), or checkboxes where only one answer is valid.

Accessibility

  • Real <input> wrapped in a <label>; the label text is part of the target.
  • Radio groups share a name and are reachable as one arrow-key group.
  • Selected state shown by fill and the control shape, never colour alone.
  • Indeterminate checkboxes set the DOM indeterminate property and aria-checked="mixed".

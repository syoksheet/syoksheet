Alert

An alert is an inline message bound to a surface or a section — explaining state, a result, or a required action. It stays in the layout; for transient confirmations that float and auto-dismiss, use a Toast.

Beta 4 tones

Anatomy

A leading status icon, a body (title + optional message), optional actions, and an optional dismiss. Tone is carried by a flat tinted background and the icon colour — never coloured body text.

Density

Two densities. Title-only for a one-line status; title + message when context is needed. Actions and dismiss are both optional.

Placement

  • Bind to context. Put the alert directly above the section or field it concerns — never float it page-top for a local issue.
  • One at a time. Don't stack multiple alerts; show the most important, or consolidate.
  • Full-width within its container, matching the card/section it sits in.
  • Inline, not modal. An alert never blocks the page. If the user must decide before continuing, that's a Modal.

Content

  • Title is the takeaway — readable on its own in a few words.
  • Message gives the next step, in plain language. No error codes or stack traces.
  • Action verb-first, matching the Button rules ("Enable 2FA", "Resend request").
  • Don't moralise or over-celebrate — "Verification complete," not "Awesome job!"

Accessibility

  • Tone is paired with an icon and a title — never carried by colour alone.
  • Error and warning alerts use role="alert" so they're announced; info/success use role="status".
  • A dismiss control is a real <button> with aria-label="Dismiss".
  • All four tinted backgrounds meet AA contrast with their title and icon colours.

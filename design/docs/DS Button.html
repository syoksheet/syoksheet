Components / Button

Button

Buttons trigger an action or a change of view. They are the most frequent point of interaction in syoksheet, so their hierarchy must always be unambiguous.

Beta 6 variants · 3 sizes

Anatomy

Every button is a single flex row: an optional leading icon, a required text label, and (rarely) a trailing icon. Labels are always present — syoksheet has no icon-only buttons except the dedicated icon-button control.

A button is a single flex row — container, optional leading icon, and label.

Variants

Six variants form one clear hierarchy. There is never more than one primary button on a surface; everything else steps down from it.

Hierarchy: primary → secondary → ghost. Verify & danger are semantic, not hierarchical.

Verify is not the primary colour. Forest green is reserved for verification actions. Never use the verify button for a generic confirm — use primary teal.

Sizes

Three sizes. Default (38px) covers almost everything; small (31px) for dense toolbars and table rows; large (46px) for marketing and primary funnels only.

States

Every button ships five states. State is signalled by fill/elevation change plus the focus ring — never by colour alone.

defaultResting. Solid teal, no shadow.
hoverDarkens one step (--teal-700).
focus-visible2px ring, 2px offset. Keyboard only.
loadingSpinner replaces leading icon; label becomes present-progressive; button stays disabled.
disabled50% opacity, no pointer. Pair with a tooltip explaining why.

Placement & order

In any footer, toolbar, or modal, buttons are right-aligned with the primary action right-most. Status text sits on the far left.

Saved · 2 mins ago
Left → right: status · tertiary (ghost) · secondary · primary.
  • One primary per surface. If two actions feel equally important, one is secondary.
  • Cancel is always ghost and sits to the left of the confirming action.
  • Destructive confirmations put the danger button right-most, with Cancel to its left.

Do & don't

Do

One primary, one secondary. Clear which action is the main one.

Don't

Two primaries compete. The user can't tell which is safe.

Do

Use the forest verify button only for verification approvals.

Don't

Don't use verify-green for non-verification actions — it dilutes the trust signal.

Content

  • Lead with a verb. "Request verification", "Add brag", "Leave organisation" — never "Submit" or "OK".
  • Sentence case, no terminal punctuation. One to three words.
  • Name the object for destructive or consequential actions: "Disband organisation", not "Disband".
  • Match the heading. A "Leave Acme Corp?" dialog's confirm button reads "Leave Acme Corp".

Accessibility

  • Use a real <button> (or <a> for navigation). Never a bare <div>.
  • Visible focus ring (2px --teal-500, 2px offset) on :focus-visible.
  • Contrast: white-on-teal and white-on-clay both meet WCAG AA (≥4.5:1). Disabled is exempt.
  • Loading buttons set aria-busy="true" and stay disabled to prevent double submits.
  • Icon-only controls require an aria-label; this button component always has a visible label.
